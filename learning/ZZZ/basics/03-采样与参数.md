# 03 · 采样与参数：temperature 到底在改什么

> **是什么**：采样参数决定"模型从概率分布里怎么挑下一个 token"。
> **为什么重要**：同一份代码、同一个模型，参数不同，跑分可能差一大截，且**不可复现**。
> **和比赛的关联**：agent 需要稳定地输出可解析的结构，随机性是把双刃剑。

## 1. 一句话结论

**temperature 调的是"敢不敢选不那么显然的词"，不是"聪不聪明"。**

## 2. 常用参数速查

| 参数 | 作用 | agent 场景建议 |
| --- | --- | --- |
| `temperature` | 拉平/锐化概率分布。0 = 几乎贪心，越大越随机 | 解析稳定性优先时取低值（0~0.3） |
| `top_p` | 只在累计概率前 p 的候选里采样 | 与 temperature 二选一调，别同时乱动 |
| `max_tokens` | 单轮补全上限 | 太小会截断 JSON，导致解析失败 |
| `seed` | 固定随机种子（部分服务支持） | 想复现实验时设置，但仍不保证 deterministic |
| `stop` | 遇到指定串停止 | 可用来防止模型"说完了还接着编" |
| `n` | 一次返回多个候选 | 用于 self-consistency 投票，成本翻倍 |

## 3. 随机性的三个真相

1. **temperature=0 不等于完全确定**：浮点计算、批处理调度、服务端版本都会带来细微差异。
2. **长输出放大不稳定性**：错一个 token，后面可能整段跑偏；所以结构化输出比自由文本更抗抖。
3. **低温度不等于低能力**：需要发散（例如想多种拆解方案）时可临时升高温度，但**执行阶段要收回**。

## 4. 调参实验的正确姿势

- [ ] 一次只改一个参数，且**固定题目集合**，否则分不清是参数还是题目难度的影响；
- [ ] 每档至少跑若干次看方差，单次结果不足以做决策；
- [ ] 记录：模型版本 + 参数 + 题集 + 分数，写成一行日志，便于回溯。
