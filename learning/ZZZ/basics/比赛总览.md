## 1. 任务长什么样

每个 task 是一个自包含的数据包 `task_xxx/`，混着多种模态：

```text
task_xxx/
├── task.json          # task_id / difficulty / question
└── context/
    ├── csv/  json/    # 结构化数据
    ├── db/            # SQLite 数据库
    ├── doc/           # 文档（Markdown 等）
    └── knowledge.md   # 业务口径定义，常是解题钥匙
```

Agent 拿到一个高层自然语言问题后，要**自己**完成：

1. **分解与规划**：把大问题拆成可执行的多步计划；
2. **选工具执行**：Python 脚本 / SQL 查询 / 其它工具；
3. **跨模态推理**：结构化表格 + 非结构化文档 + 图表联合推理；
4. **综合出答案**：产出最终答案表 `prediction.csv`。

## 2. 怎么算分

```text
Score = max(0, Recall − λ × Extra / Predicted)      λ 复现口径 0.5（官方只公开符号 λ）
Recall = 命中列数 / gold 列数；Extra = 预测列数 − 命中列数
```

- 列按**内容签名**匹配：值归一化后作多重集比较，忽略列名 / 行序 / 列序，一对一匹配；
- **多给列会被罚分**，所以答案是"宁缺勿滥"；
- 分数下限为 0；
- 本地同口径评分器：`code/competitions/evaluation/`，并已融合进 `run-benchmark`（跑完自动出分）。

## 3. 难度分级

| Level | 主要模态 | 核心挑战 |
| --- | --- | --- |
| Easy | JSON/CSV + 知识文档 | 代码生成类：把问题翻译成正确的 Python |
| Medium | JSON/CSV + SQLite + 文档 | Text-to-SQL 与多源结果对齐 |
| Hard | 上述全部 + 长篇数据/知识文档 | 长上下文下的非结构化推理 |

## 4. 为什么"线性 ReAct"不够用

| 推理拓扑 | 说明 |
| --- | --- |
| Sequential Chain | A→B→C 逐步依赖，误差一路向下游传播 |
| Branching & Merging | 并行子查询（SQL 一路、文档一路）再汇合 |
| Iterative Loop | 发现不对就回溯重来 |

真实数据分析是 **DAG**，不是单线条——这是自研方案最主要的发力点。
