## 1. Agent 主循环（ReAct Loop）

### 1.1 循环三件套

每一轮固定四步：
1. 把 `system + 历史` 发给 LLM；
2. 解析出 `thought / action / action_input` 三件套；
3. 执行工具、拿 Observation；
4. Observation 追加进历史，回到 1。

### 1.2 消息重放机制

**模型没有记忆**（见 `basics/02`）：每一轮都把**全部历史**重新发给模型。
所以上下文随轮次线性膨胀——这是成本与长任务瓶颈的根源，也是自研要做 observation 截断的原因。

### 1.3 解析失败怎么自救

设计是"解析宽容 + 错误回灌"：

```
模型输出不能解析
  └→ 把"解析失败"作为 Observation 回灌
      └→ 模型自行修正，重试
```

实测效果：任务全程 4 次解析失败全部自愈，最终收敛到答案。
代价：每次都重发全部历史（回灌越多，越贵越慢）。

### 1.4 终止的三个出口

| 出口 | 条件 | 产物 |
| --- | --- | --- |
| 正常 | 模型输出 `action=answer` | prediction.csv |
| 截断 | 超过 max_steps | 失败（无答案） |
| 超时 | 超过 task_timeout | 失败（无答案） |

**教训**：单次跑通 ≠ 稳定跑通（`basics/03`）；agent 必须批量跑看通过率。

## 2. 工具系统

### 2.1 8 个工具一览（读 / 写 / 执行三类）

| 类别 | 工具 | 用途 |
| --- | --- | --- |
| 查看 | `list_context` | 列出 context 目录结构 |
| 读 | `read_text` / `read_csv` / `read_json` / `read_table` / `read_doc` | 按格式读数据，默认只读前几行 |
| 执行 | `execute_python` | 在沙箱子进程跑 Python（当数据库/Excel 用） |
| 产出 | `answer` | 唯一终止出口，提交最终答案 |

### 2.2 三层安全边界（架构层请看这）

| 层 | 防什么 | 手段 |
| --- | --- | --- |
| 路径 | 逃逸出数据目录 | 所有读操作限制在 task 的 context 内，路径越界即拒绝 |
| SQL | 写操作/注入 | 只读连接、禁危险 SQL 关键词 |
| Python | 死循环/崩溃/越权 | 独立子进程执行 + 超时强杀（`basics/05`） |

**自研启示**：工具是 agent 的"手"，安全边界必须从第一天就设计好——尤其 execute_python。

## 3. 提示词工程

### 3.1 三层组装

```
system（角色+规则+工具说明+输出格式样例）
  + user（问题 task.json）
  + 历史（thought/action 记录 + Observation）
```

每条规则的设计目标只有一个：**让模型稳定输出 `{thought, action, action_input}` 的合法 JSON**。

### 3.2 为什么拆三部分

| 部分 | 作用 | 换个角度 |
| --- | --- | --- |
| 规则类 | 约束输出格式 | 和解析器一起构成"协议" |
| 工具说明 | 教模型用工具 | 相当于"API 手册" |
| 样例（few-shot） | 示范完整一轮 | 让模型模仿行为模式 |

### 3.3 官方方案的已知短板

- **结构化依赖自由文本 JSON**：模型可能夹带开场白/不转义引号/输出被截断
  → 6 类解析故障（详见 patches.md 的启示）；自研 v0.1 用 Function Calling 从根上解决（详见 `basics/04`）；
- **没有 execute_python 的 few-shot 示例**：对这套工具熟悉度不够的模型会写得生涩。

## 4. 评测流程

### 4.1 一次跑分的两级调度

```
run-benchmark（批量）
  └─ 线程池并发多任务
      └─ 每任务独立子进程 + 超时
```

好处：单题崩溃/超时不影响整批；坏处：并发数受后端限流约束。

### 4.2 评分公式（务必背下来）

```
Score = Recall − 0.5 × (Extra列数 / 预测列数)
```

| 关键点 | 含义 |
| --- | --- |
| 比对对象 | 标准答案的**列集合**（multiset，忽略顺序） |
| Recall | 预测列 / 标准列命中率 |
| **罚分** | 多猜的列越多，扣分越狠（宁缺勿滥） |
| Micro vs Macro | 按样本加权 / 按任务平均，结果可能差很多 |

### 4.3 产物契约

每跑一题在 `artifacts/runs/<run_id>/task_XX/` 留下：
- `prediction.csv` —— 最终答案（提交物）；
- `trace.json` —— 完整轨迹（thought/action/observation），是排错与复盘的核心证据；
- `run.json` —— 元信息（耗时、token、模型）。

> 失败复盘 = 看 trace.json 找"思维在哪一步断了"，结合 experiments-log 记录。
